# FE API 연동

기준 명세: [Notion API 명세서](https://app.notion.com/p/ff300a83351d82ed931f813c04a59410)

기존 CSS, SVG, 사진 자산과 화면 배치는 수정하지 않았다. 페이지에서는 데이터 바인딩, 요청 처리, 로딩·오류·중복 제출 방지와 서버 상태에 따른 이동만 연결한다.

## 실행 설정

`.env.example`을 참고하여 저장소 루트에 `.env.local`을 만들고 다음 값을 설정한다.

```dotenv
VITE_API_MODE=api
VITE_API_BASE_URL=
VITE_PLACE_IDS={}
```

- `VITE_API_BASE_URL`: 실제 API 서버의 공통 접두사까지 포함한 주소. 현재 전달되지 않았으므로 코드에 서버 주소를 추측해서 넣지 않았다.
- `VITE_PLACE_IDS`: 서버에서 받은 실제 건물명과 숫자 ID의 JSON 객체. 장소 조회 API가 명세에 없어 환경 설정을 통해 공급한다. 입력한 장소가 `건물명 상세위치` 형식이면 건물명을 찾아 `place_id`와 `location_detail`로 나눈다. 알 수 없는 건물은 등록 요청 전에 오류를 안내한다. 임의 숫자를 실제 ID로 전송하지 않는다.
- 환경 변수 변경 후 `npm run dev`를 재시작한다. 배포 시에도 빌드 환경에 같은 값을 설정해야 한다.
- 서버는 FE origin과 `Authorization`, `Content-Type`, `GET/POST/PATCH/OPTIONS` 요청에 대한 CORS 설정이 필요하다. FE에서 CORS 보안을 우회하지 않는다.

서버 정보가 없을 때는 `VITE_API_MODE=mock`으로 기존 UI를 확인할 수 있다. 기본값은 mock이다. API 모드의 오류를 mock 데이터나 성공 응답으로 대체하지 않는다. API 모드에서 주소가 비어 있으면 설정 오류를 안내한다.

분실물 입력 미리보기에서는 실제 입력한 종류·색상·브랜드·장소·날짜와 선택한 사진을 요약 및 다음 화면까지 유지한다. 입력하지 않은 정보에 이어폰·삼성 등 고정 예시를 대신 넣지 않는다. 새 미리보기에는 별도의 로컬 ID를 부여하고, 관련 없는 이어폰 후보를 연결하지 않는다. 미리보기는 AI 분석이나 서버 저장이 아니며 화면에도 이를 표시한다.

## 연결 내용

- 공통 요청: JSON·multipart, Bearer 토큰, 취소·시간 제한, 필드별 검증 오류·401·권한 오류·서버 오류 안내. 변경 요청은 자동 재시도하지 않는다.
- 인증: 이메일 코드 발송·검증, 성공한 경우에만 로그인, 현재 탭의 sessionStorage 보관, 로그아웃과 인증 만료 시 로그인 이동. refresh API가 명세에 없어 임의의 갱신 요청은 만들지 않았다.
- 홈: 최근 습득물과 매칭 건수, 실제 프로필 이름. 후보가 있는 등록이 한 건이면 해당 분실물 ID를 전달하고, 여러 건이면 마이페이지에서 선택한다.
- 조회: 습득물 목록 페이지네이션, 프로필·분실/습득 등록 건수·반환 완료 내역, 알림 목록·개별/전체 읽음 처리.
- 마이페이지: LOST/FOUND ID가 같은 경우도 유형을 보존한다. 카드 클릭 때 상태를 다시 조회하고 서버의 `next_action`에 있는 채팅 ID로 이동한다.
- 분실물: 대표 사진 분석 또는 텍스트 입력 → 특징 대화 → 등록 → 실제 등록 ID로 결과와 후보 조회. 서버 질문과 선택지 및 최종 특징을 사용한다.
- 습득물: 대표 사진을 multipart로 분석하고 서버의 블러 처리 이미지·태그를 표시한다. 사용자가 수정한 값과 비공개 특징을 등록 요청에 담는다. 사진을 바꾸면 새 사진을 분석한 뒤 새 `image_id`를 사용한다.
- 등록 시 날짜와 실제 선택한 시간을 모두 요구한다. 시간 입력을 생략했다고 임의의 시각을 전송하지 않는다. 선택한 시각은 한국 시간 `+09:00`으로 전송한다. 사진 API는 한 장만 받으므로 최대 3장 중 대표 사진 한 장을 전송한다.
- 매칭: 현재 등록 건의 후보 목록·상세·제외 처리. 분실물 ID를 이동 상태로 보존한다.
- 소유권: 서버에서 받은 여러 질문을 차례로 입력하고 모든 답변을 모아 제출한다. `NEED_MORE`이면 같은 확인 건으로 추가 질문에 답하고, `MATCHED`인 경우만 반환 연결로 이동한다. 실패·잠금 응답을 성공으로 처리하지 않는다. 실제 API 모드에서 검증 건너뛰기는 허용하지 않는다.
- 채팅: 생성·메시지 조회/전송·반환 완료. 조회는 5초 간격이며 겹치는 조회를 막는다. 서버에 없는 장소·시간은 추측해서 표시하지 않고 채팅 내용을 확인하도록 안내한다.

## 아직 서버 계약이 필요한 기능

- 실제 Base URL과 장소 ID 목록: 현재 전달되지 않았다. 이 값 없이는 실제 서버 연결과 물건 등록을 완료할 수 없다.
- 습득자가 확인하는 분실물 후보 목록·상세: 해당 조회 endpoint가 명세에 없다. 기존 화면은 유지하고 API 모드에서는 명세 필요 안내를 표시한다.
- 채팅 목록: 별도 endpoint가 없어 내 등록 상태의 `GO_TO_CHAT` 대상과 반환 완료 내역을 합쳐 구성한다. 안읽음/읽음 상태 API는 없어 안읽음 필터에 제한을 안내한다.
- 구조화된 반환 약속 장소/시간, 채팅 상세의 습득 장소, 반환 내역의 장소/전달 방법: 응답에 없다. 예전 mock 값으로 채우지 않는다.
- 등록 후 정보 수정 API와 토큰 갱신 API: 명세에 없다. 요청을 추측해 만들지 않았다.
- 습득물 공개 상세 GET 함수는 준비되어 있다. 현재 목록의 카드에는 공개 상세 화면이 없어 새 디자인을 추가하지 않고 기존 동작을 유지한다.
- 개발용 수동 매칭 endpoint는 제품 UI에 연결하지 않았다.

## 검증

```bash
npm test
npm run lint
npm run build
```

`tests/fixtures/api-contracts.json`은 제공된 명세의 예제이며 실제 사용자나 인증 정보가 아니다. 테스트는 모든 HTTP 요청을 로컬 함수로 가로채고 실제 메일 발송·실제 서버 등록을 하지 않는다. 실제 API 모드의 service까지 검사하며 인증, 페이지네이션, 동일한 분실/습득 ID, 여러 소유권 질문·추가 질문, 메시지/반환, 원본 파일 업로드·블러 이미지, 미설정 장소, HTTP 오류·인증 만료·시간 초과를 확인한다.

실제 서버와의 통합 검증은 서버 주소 전달 후 별도로 필요하다. 임시 서버를 사용한 브라우저 전체 흐름 검증은 실행 환경의 네트워크 제약으로 완료하지 못했으며, 인증 요청 실패가 기존 화면에 표시되는 것만 확인했다.
